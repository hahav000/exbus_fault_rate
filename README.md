# 고속버스 단말기 장애실적 대시보드

`고속 시외 YYYY년.xlsm` 파일의 **고속Rawdata** 시트를 읽어 Streamlit 대시보드로 보여줍니다.
`E-PASS고속수리_2026.xlsx`(수리센터 재불량 로그)가 같은 폴더에 있으면, 외장 LTE모뎀 전환과
수리포인트가 필드 장애에 실제로 미친 효과까지 함께 분석합니다.

파일은 폴더에 두는 대신 **사이드바에서 직접 업로드**할 수도 있습니다(장애접수 엑셀 최대
2개 + 수리현황 엑셀) - 업로드하면 폴더의 파일 대신 그것을 씁니다. 핵심 차트 5장을 브리핑용
**PPT(.pptx)**로 한 번에 뽑는 기능도 있습니다(사이드바의 **📊 PPT 보고서 생성**).

## 실행

```powershell
pip install -r requirements.txt
streamlit run app.py
```

브라우저에서 `http://localhost:8501` 이 열립니다.

## 매주 갱신 반영

엑셀 파일을 **같은 이름으로 덮어쓰기만** 하면 됩니다.
파일의 수정시각·크기를 캐시 키로 쓰기 때문에, 파일이 바뀌면 다음 접속 때 자동으로 다시 읽습니다.
바로 반영하고 싶으면 사이드바의 **🔄 새로고침** 버튼을 누르세요.

연도 파일이 늘어나도(`고속 시외 2027년.xlsm` 등) 폴더에 두기만 하면 자동으로 합쳐집니다.
`E-PASS고속수리_2026.xlsx`도 같은 방식(같은 이름으로 덮어쓰기 / `E-PASS고속수리*.xlsx` 자동 탐색)입니다.

**폴더에 파일을 두는 대신, 매번 사이드바에서 업로드해도 됩니다** - 상단 **📤 파일 업로드**에
장애접수 엑셀(최대 2개, `.xlsm`/`.xlsx`)과 수리현황 엑셀(`.xlsx`)을 끌어다 놓으면 폴더의
파일 대신 그것으로 대시보드가 다시 그려집니다. 업로드 칸을 비워 두면 이전처럼 폴더의 파일을
그대로 씁니다 - 둘 중 편한 방식을 그때그때 골라 쓸 수 있습니다.

> 엑셀에서 파일을 열어 둔 채여도 읽기는 되지만, 저장 중이라면 잠깐 실패할 수 있습니다.
> 그때는 저장이 끝난 뒤 새로고침하세요.

이 탭이 비어버리기 때문에, 기간·지역·고속사 등 나머지 필터만 함께 받고 항상 이 4종을 보여줍니다.
**개선효과** 탭은 사이드바 필터를 아예 보지 않고 항상 전체 기간을 봅니다 — 수리 로그의 단말기
S/N에는 지역·고속사 정보가 없어 필터를 걸 수가 없기 때문입니다.
모든 차트에는 `표로 보기 · 내려받기`가 붙어 있어 수치를 그대로 확인하고 CSV로 받을 수 있습니다.

## 데이터 해석 규칙

- **시트 규격**: 3행이 헤더, 4행부터 데이터. `B열(No.) ~ AF열(베이스플레이트)`.
- **주차**: 원본 `주차` 칸(예: `3월2주`)을 그대로 씁니다. 이 업무의 주차는 **목요일에 시작**하므로
  12월 말 날짜가 `1월1주`로 잡힙니다. 연말/연초가 섞이지 않도록 라벨과 날짜의 월이 어긋나면
  연도를 보정해 정렬 키를 만듭니다.
- **월·연도**: 원본 `월` 칸에 공백 변형(`1월`/`1월 `)이 있어, `일자`에서 다시 계산합니다.
- **표기 정규화**: 수기 입력 오타·공백 때문에 집계가 갈라지지 않도록 아래를 통합합니다.
  전체 목록은 대시보드 **데이터 탭 → 표기 정규화 내역**에서 볼 수 있습니다.

  | 컬럼 | 예 |
  |---|---|
  | 처리지역 | `세트럴`·`센터럴`·`센트를`·`센틀럴` → `센트럴`, `광주` → `광주터미널` |
  | 처리거점 | `인전` → `인천`, `경부선`(지역명 오기) → `서울` |
  | 고속사 | `금혹고속` → `금호고속`, `경부선`·`동서울`(지역명 오기) → `(미확인)` |
  | 처리담당자 | `이경핀` → `이경필`, `박벙태` → `박병태`, `김선곤` → `김성곤` |
  | 처리 대분류 | `GPS 안테나 교체`·`GPS안테나 교체` → `GPS안테나교체` 등 |

  **원본 엑셀 파일은 수정하지 않습니다.** 읽어 들인 뒤 메모리에서만 정규화합니다.

- **데이터 범위 주의**: `고속 시외 2025년.xlsm` 에는 2023-12-28 ~ 2025-12-31 이 모두 들어 있어
  실제로는 2024·2025 두 해 치입니다. 2023-12 분 17건은 원본에서 `1월1주`로 편입된 4일치라,
  연도별 비교 선 그래프에서는 제외하고 표에는 남겨 둡니다.

## 개선효과 분석 방법

세 가지 서로 다른 방식으로 "조치가 실제로 통했는가"를 봅니다.

### 1. 외장 LTE모뎀 전환 · B/D(AFC/BMS) 보드교체 — `고속Rawdata` 텍스트에서 직접 추출

`세부 조치 내용 (현장 확인 증상 / 조치내용)` 칸의 자유 텍스트에 아래 문구가 박혀 있습니다
(오타 변형도 정규식으로 함께 잡습니다 - `data_loader.extract_intervention_events`):

| 문구 | 의미 |
|---|---|
| `외장모뎀적용` | 이번 조치로 외장 LTE모뎀을 **새로** 장착 (신규 전환) |
| `외장모뎀적용차량` | 이 차량은 **이미** 외장모뎀이 적용된 상태라는 맥락 표기 (신규 전환 아님) |
| `B/D교체적용` | 운전자단말기 내 AFC보드·BMS보드 중 하나 이상을 교체 |

이 방식으로 신규 전환 **301건(289대)**, B/D 보드교체 **76건(73대, 외장모뎀 동반 45건·단독
31건)**을 찾았습니다 — 장애/처리 대분류에 '외장'이 들어간 기록(16건)만 보던 이전 버전보다
훨씬 정확합니다. 장애 대분류·처리 대분류 필터만으로는 이 정보가 잡히지 않으니 반드시 이
텍스트 패턴으로 찾아야 합니다.

### 2. 조치 전/후 비교 (`data_loader.vehicle_event_study`) — 가장 직접적인 효과 검증

차량별로 조치 시행일 기준 **전/후 90일** 동안 관심 장애(LTE·BMS·승차연결지연) 발생 건수를
비교합니다. 설치 직후 **14일**은 같은 방문의 재작업일 수 있어 '후' 집계에서 뺐고, 조치 후
90일을 채우지 못한(최근에 조치한) 차량은 관찰기간 부족으로 제외합니다(우측 절단 방지).

결과가 흥미롭게 갈립니다:

- **외장모뎀 신규전환**: 차량당 평균 발생건수가 **0.10건(전) → 0.13건(후)**로 오히려 늘어
  개선 신호가 뚜렷하지 않습니다. 신규전환의 56%가 LTE모뎀망연결지연 고장을 계기로 이뤄져
  표본 자체가 문제 차량에 쏠려 있는 데다(선택편향), 표본이 작아(차량당 0.1건대) 몇 대의 우연한
  재발에도 비율이 크게 흔들립니다.
- **B/D 보드교체**: 반대로 뚜렷한 개선을 보입니다 — 단독 시행(외장모뎀과 무관) 기준
  **0.38건(전) → 0.00건(후)**. 우연만은 아닌 것으로 보입니다.

둘 다 정식 대조군 비교가 아니라 참고용 신호이며, 대시보드에도 이 해석을 그대로 caption·경고
박스로 표시했습니다.

### 2-1. 수리 방식별 60일 내 현장 재발률 (E-PASS 수리 로그 `주 수리 내역` 기준)

**주의 - `B/D`라는 이름이 두 군데서 서로 다른 보드를 가리킵니다.** E-PASS 수리 로그의
`주 수리 내역`에 나오는 `Main B/D`(수리/교체)는 운전자단말기의 **메인보드**(LTE모뎀 회로가
실장된 보드) 전체를 가리키며, 방식 1의 `B/D교체적용`(AFC보드·BMS보드)과는 **다른 물리 보드**
입니다. 이름이 같다고 혼동하면 안 됩니다.

- `Main B/D 수리`(재작업/재납땜, 459건): 60일 재발률 **13.7%**
- `MODEM`(모뎀만 교체, 47건): 60일 재발률 **13.8%**
- `Main B/D 교체`(보드 통째로 교체, 20건): **전부 2026-08-31 하루에 일괄 시행**돼서 아직 60일이
  안 지나 재발률을 계산할 수 없습니다(관찰가능 0건) — 대시보드에는 이 사실을 그대로 표시하고
  차트에서는 뺍니다(표에는 남아 있음).

### 3. E-PASS 수리 ↔ 장애실적 상관관계 — S/N 매칭

두 데이터를 잇는 열쇠는 **단말기 S/N**입니다. `E-PASS고속수리_2026.xlsx`의 `B610 고속 운전자
재불량` 시트가 개별 단말(S/N)의 수리 이력을, `고속Rawdata`의 `교체전`/`교체후` 칸이 현장에서
그 S/N이 언제 빠지고 들어왔는지를 담고 있어 — 같은 체계의 9자리 번호입니다(수리 로그 SN의
88%가 필드 데이터의 교체전/교체후에서 실제로 발견됩니다).

- **수리센터 내 재불량률**: 수리 로그의 `재불량` 칸이 문자로 찍힌 건 — 1차 수리 후 재검사에서
  다시 불량으로 잡혀 재작업한 비율입니다. 수리센터를 떠나기 전에 걸러진 것이라 **필드 재발과는
  다른 지표**입니다.
- **60일 내 현장 재발률**: 각 수리 건의 `수리일` 이후, 같은 S/N이 `교체전`으로 다시 잡히는 첫
  시점을 `merge_asof`로 찾아 경과일을 계산합니다. 최근 수리일수록 아직 60일이 안 지나 재발 여부를
  알 수 없으므로(우측 절단·censoring), **수리일로부터 60일 이상 지난 건만** 분모에 넣습니다 —
  이 때문에 최근 1~2개월 치는 이 지표에서 제외됩니다(표에는 남아 있음).
- 재발로 잡힌 건 중 절반 가까이는 애초 수리한 것과 **다른 증상**(주로 운전자화면불량)으로
  잡힙니다. 그래서 60일 재발률은 "그 수리가 실패한 비율"이 아니라 **상한선**으로 읽어야 합니다.

이 계산들은 `data_loader.py`의 `extract_intervention_events` / `vehicle_event_study`
(방식 1·2)와 `load_repair_data` / `build_recurrence`(방식 3)에 있고, 화면은 `app.py`의
**개선효과** 탭 전체가 담당합니다.

## PPT 보고서 생성

사이드바의 **📊 PPT 보고서 생성** 버튼을 누르면 아래 5장을 표지 1장과 함께 `.pptx`로 묶어
**⬇️ PPT 다운로드** 버튼으로 내려받을 수 있습니다(생성에 10~20초 걸립니다 - 차트를 정적
이미지로 그려 넣기 때문입니다).

1. 연도별 월간 추이 비교
2. 월별 장애 건수 (전체 기간)
3. 관심 장애유형 - 월별 구성 (전체 기간)
4. 외장 LTE모뎀 전환 · B/D(AFC/BMS) 보드교체 현황 (차트 2개를 한 슬라이드에)
5. 조치 전/후 관심 장애 발생률 비교

각 슬라이드에는 차트 옆에 핵심 수치를 요약한 글머리 기호 2~6줄이 자동으로 붙습니다(예:
"2026년 누계 684건 (부분 기간)", "외장모뎀 신규전환: 0.10 → 0.13 (악화)").

**항상 전체 기간·업로드/폴더의 원본 데이터 그대로**를 씁니다 - 사이드바의 기간·지역·고속사
필터는 보고서에 반영되지 않습니다. "보고서 생성" 버튼을 누른 시점에 우연히 걸려 있던 필터에
따라 내용이 달라지면 안 되기 때문입니다. 데이터가 없어 만들 수 없는 슬라이드(예: 수리 로그가
없어 계산 불가능한 경우는 없지만, 관심 장애유형이 0건인 경우 등)는 조용히 건너뜁니다.

만들어지는 파일은 항상 라이트 팔레트로 고정됩니다(다크모드로 보고 있어도) - 프린트/투사
환경의 흰 배경 슬라이드에 맞춘 것입니다. 슬라이드는 16:9이고, 본문 폰트는 맑은 고딕입니다.
로직은 `report_builder.py`(슬라이드 데이터 계산)와 `ppt_export.py`(python-pptx + kaleido로
실제 파일 조립)에 있습니다.

## 파일 구성

```
app.py                        대시보드 화면 (파일 업로드 · 필터 · KPI · 7개 탭 · PPT 버튼)
data_loader.py                엑셀 적재(경로/업로드 공통) + 표기 정규화 + 캐시 + 수리 로그 상관분석
report_builder.py             PPT 보고서용 슬라이드 데이터 계산 (라이트 고정 · 전체 기간 고정)
ppt_export.py                 슬라이드 데이터를 .pptx 파일로 조립 (python-pptx + kaleido)
charts.py                     차트 빌더 (막대 / 라인 / 누적 / 히트맵 + 표 보기)
viz_theme.py                  팔레트와 Plotly 공통 레이아웃
.streamlit/config.toml        라이트·다크 테마 색
```

### 색 규칙

브라우저/OS의 라이트·다크 설정을 따라가며, 차트 팔레트도 같은 값을 읽으므로 항상 일치합니다.

- 카테고리형은 **고정 슬롯 순서**로만 배정합니다 — 필터를 바꿔도 같은 항목은 같은 색을 유지합니다.
- 꼬리를 묶은 `기타`는 중립 회색으로 두어, 색 슬롯은 실제 범주에만 씁니다.
- 히트맵은 파랑 한 가지의 명도 램프 + 스케일 범례를 씁니다(무지개 금지).
- 축은 하나만 둡니다. 막대와 이동평균선은 **같은 단위**라 한 축에 함께 그립니다.

## 알아두면 좋은 점

- 첫 실행은 엑셀 파싱에 10초쯤 걸립니다. 이후에는 디스크 캐시라 앱을 껐다 켜도 즉시 뜹니다.
- 자재(부품) 사용량 칸은 2026년 파일에 아직 입력되어 있지 않습니다.
  기간 필터를 2026년으로 좁히면 "입력되어 있지 않습니다" 안내가 나옵니다.
- 시외 데이터(`시외Rawdata`)는 이 대시보드에 포함하지 않았습니다.
  필요하면 `data_loader.SHEET` 를 바꾸거나 시트를 하나 더 읽도록 확장하면 됩니다.
- **관심 장애유형 4종**(`LTE모뎀망연결지연`·`BMS접속지연`·`승차연결지연`·`승차단말기통신불량`)이
  전체 장애의 **56%**를 차지하며, 이 중 `LTE모뎀망연결지연` 하나가 전체의 **48%**입니다.
  네 종류 모두 통신/연결 계열이라 `app.py`의 `FOCUS_FAULTS` 목록만 바꾸면 다른 유형 조합으로도
  같은 화면을 재사용할 수 있습니다.
- **수리포인트 효과**: E-PASS 수리 671건 중 56%가 LTE/모뎀 계열이고, 60일 내 현장 재발률은
  2026년 3월 14% → 6월 6%로 낮아지는 추세입니다(2월은 표본 6건뿐이라 참고용). 다만 재발로 잡힌
  건의 46%만 같은 LTE 계열이라, 이 수치를 "수리 실패율"로 그대로 읽기보다는 상한선으로 보세요.
- **조치별 전/후 비교의 핵심**: 외장 LTE모뎀 신규전환(301건)은 차량별 전/후 비교에서 개선
  신호가 뚜렷하지 않은 반면, B/D(AFC/BMS) 보드교체(76건)는 단독 시행 기준 0.38건→0.00건으로
  뚜렷하게 개선됩니다 — 자세한 해석은 위 "개선효과 분석 방법" 참고.
- **운영 차량 추정치**: 사용자가 제공한 값으로, 고속사별 매달 대수가 바뀌지만 대략 **2,000대**
  (`app.py`의 `FLEET_SIZE_EST`). 정확한 값이 아니므로 커버리지(전환률 등)를 어림잡는 참고용
  캡션에만 쓰고, 정밀한 분모로 쓰지 않습니다. 값이 바뀌면 이 상수만 고치면 됩니다.
- `E-PASS고속수리_2026.xlsx` 파일이 없으면 **개선효과** 탭의 외장모뎀·B/D보드교체 섹션(장애실적
  텍스트에서 바로 뽑으므로 항상 표시)만 보이고, 수리포인트 섹션은 안내 문구로 대체됩니다 —
  에러가 나지 않습니다.
